# Dev2: final band handoff and readiness checklist

Get the real Thrifted Tease assets, collect the band's creative input, and finish merch and media before calling dev2 ready.

## 1. Collect everything in one place

Use one shared folder with **Brand**, **Merch**, and **Media** subfolders. Track each request with an owner, link, status, and agreed due date. Statuses: **Needed → Received → Ready for review → Approved**. Leave due dates unset until agreed with the band.

### Spencer — brand assets

- [ ] Share album/single artwork, logos, Canva links, fonts, and any existing posters or graphics that capture the band's identity.
- [ ] Include original files and high-resolution exports; transparent logos where available.
- [ ] Mark which designs are current and which are old references.

**Checkpoint:** Hamza can access the files and knows which assets should define the site.

### Hamza — shirts and Square

- [ ] Confirm the actual products, names, prices/currency, sizes, inventory, sizing information, and shipping/pickup arrangements.
- [ ] Set up the Square catalogue and provide a working checkout link for each product, following the [Square integration checklist](square-integration-checklist.md).
- [ ] Collect real front, back, and print-detail photos of each shirt in consistent lighting.
- [ ] Replace placeholder mockups and Shopify references with real photos, product copy, and Square links.
- [ ] Present shirts against a clean, consistent background. Use a subtle lift/zoom on hover and keyboard focus; provide a visible way to inspect alternate photos on mobile. Respect reduced-motion preferences.

**Checkpoint:** Every listed shirt looks like the actual product, and a customer can choose an available size and complete checkout.

## 2. Get the band's colour input

### Kevin, Bennett, Hamza, Spencer — each reply with

- [ ] Two or three colours that feel like Thrifted Tease.
- [ ] One or two visual references: artwork, clothing, posters, or websites.
- [ ] Colours to avoid, including an opinion on the current gold.

### Hamza — turn responses into a decision

- [ ] Prepare two palette previews using the actual band assets on a homepage section and merch card.
- [ ] Aim for vibrant, vintage, Patagonia-inspired colour combinations while keeping text easy to read.
- [ ] Record one agreed palette before applying it across all four pages.

**Checkpoint:** Everyone has been asked, the chosen palette is recorded, and text/buttons remain readable. Hamza's dislike of gold is an input; gold is not treated as an agreed band preference.

## 3. Curate and label the media

### Everyone contributes; Hamza consolidates

- [ ] Share favourite existing photos, new photos, and direct YouTube video links.
- [ ] For each selection, supply a title, show/session name, date if known, short caption, and photographer/videographer credit where applicable.
- [ ] Flag existing material as **Keep**, **Remove from website**, or **Unsure**.
- [ ] Prioritize strong performances and band photos; remove repetitive images and weak B-roll from the public page.
- [ ] Replace playlist-position embeds with specific, verified videos so captions match what plays.
- [ ] Lead with a small featured video selection, followed by curated show/session galleries. Remove empty placeholders and generic development copy.

**Checkpoint:** Every published item has an accurate label and caption, new material is represented, and videos play correctly. Removed selections stay in the source archive unless deletion is explicitly agreed.

## 4. Final dev2 review

### Hamza verifies; Kevin, Bennett, Hamza, and Spencer review

- [ ] Brand assets and the agreed palette are applied consistently.
- [ ] Merch images, prices, sizes, stock behaviour, and Square checkout are verified on desktop and mobile.
- [ ] Hamza verifies an order, receipt, fulfillment settings, and inventory update.
- [ ] Media captions, credits, video matches, and photo viewing are checked.
- [ ] Hover, keyboard focus, touch interactions, and reduced-motion behaviour work.
- [ ] Kevin, Bennett, Hamza, and Spencer review the preview; Hamza tracks and resolves launch blockers.

**Checkpoint:** The band has reviewed the preview and all launch blockers are resolved.

Keep the existing static site and Square-hosted checkout approach. No new backend or public API is planned. Due dates are agreed with the band rather than invented.
